# HTTP Request Capture

一款强大的 Chrome 扩展，用于捕获、查看和分析浏览器发出的 HTTP 请求。支持拦截 fetch 和 XMLHttpRequest 请求，捕获请求头、请求体、响应头等详细信息，并提供多种格式导出和请求重放功能。

## 功能特性

### 请求捕获
- **自动拦截**：自动捕获页面发出的所有 fetch 和 XHR 请求
- **请求头捕获**：捕获完整的请求头信息（包括 Cookie、Authorization 等敏感头）
- **请求体捕获**：支持 JSON、表单数据（URL-encoded）、FormData（multipart）格式的请求体
- **响应头捕获**：捕获完整的响应头信息（包括 Set-Cookie 等）
- **页面上下文**：记录发起请求时的页面标题（Page Title）和页面 URL
- **点击溯源**：自动关联用户点击操作与后续触发的请求，记录触发元素的标签、文本、ID、选择器等
- **webRequest 兜底关联**：点击事件会同步上报到后台，无法经过 fetch/XHR 注入层的脚本、图片、路由资源等请求，也会按同一标签页和时间窗口归入最近一次点击
- **重定向链**：追踪请求的重定向链路
- **SPA 支持**：自动追踪 History API（pushState/replaceState）和 hashchange 导航
- **iframe 支持**：正确识别 iframe 中的父页面 URL
- **操作/API 映射**：自动将用户点击与后续请求关联，按页面模块聚合查询、编辑、保存等操作对应的 API。支持并发追踪（最多5条链）、双阈值过期控制（15秒硬上限 + 3秒请求间隔软上限）、100ms 防抖

### 请求列表
- **域名分组**：按域名自动分组，支持展开/折叠
- **实时推送**：使用 Chrome Extension 端口推送，捕获即显示
- **搜索过滤**：支持按 URL、状态码、方法、页面标题、触发元素文本搜索
- **方法筛选**：按 HTTP 方法（GET/POST/PUT/DELETE 等）筛选
- **静态资源过滤**：一键过滤图片、样式表、脚本等静态资源
- **批量选择**：支持全选/取消全选，批量导出
- **语言切换**：弹窗右上角支持中文/英文界面切换，并会记住用户选择

### 详情面板
- **请求 URL**：完整显示请求地址
- **基本信息**：方法、状态码、类型、时间、页面标题、页面 URL
- **请求头**：以表格形式展示所有请求头
- **请求体**：支持 JSON/表单/原始数据显示，语法高亮
- **响应头**：以表格形式展示所有响应头
- **触发来源**：显示触发请求的页面元素信息（元素类型、文本、ID、选择器等）
- **查询参数**：解析并展示 URL 查询参数
- **重定向链**：展示完整重定向路径

### 导出格式
- **Postman Collection v2.1**：导出为 Postman 集合格式，支持 URL-encoded 和 multipart 表单数据
- **HAR (HTTP Archive)**：导出为标准 HAR 格式，包含完整的请求/响应头和 Cookie 信息
- **cURL**：一键复制为 cURL 命令，兼容 Windows cmd/PowerShell/bash

### 代理重放
- 支持将捕获的请求转发到指定目标服务器
- 路径映射：支持请求路径替换
- 自定义 Cookie：为重放请求添加自定义 Cookie
- 一键发送：从详情面板直接发送请求到代理目标

### 数据持久化
- **双存储策略**：请求数据写入 `chrome.storage.local`（浏览器重启后保留），Service Worker 重启后会从本地存储恢复列表
- **捕获状态会话保持**：`isCapturing` 写入 `chrome.storage.session`，用于 Service Worker 重启后恢复捕获状态；浏览器关闭后会话状态清除
- **防抖写入**：500ms 防抖，避免高频写入影响性能
- **等待队列**：popup 连接时若 loadState 未完成，挂起回调到 `stateLoadedCallbacks` 队列，完成后批量发送 INIT
- **配额保护**：local storage 写入失败时自动截断到 50 条

## 安装

### 开发者模式安装
1. 克隆或下载本项目
2. 打开 Chrome 浏览器，访问 `chrome://extensions/`
3. 开启「开发者模式」（右上角开关）
4. 点击「加载已解压的扩展程序」
5. 选择项目根目录

## 使用方法

### 启动捕获
1. 点击浏览器工具栏中的扩展图标，打开弹出面板
2. 点击「启动」按钮（或从停止状态点击「启动」）
3. 刷新页面或操作页面触发网络请求
4. 请求将实时显示在列表中

### 查看请求详情
- 点击列表中的任意请求行，右侧滑出详情面板
- 详情面板只会在点击面板内的关闭按钮时收起；即使点击网页导致扩展弹窗关闭，下次打开也会恢复上一次选中的请求详情
- 在详情面板中可查看：
  - 请求 URL 和基本属性
  - 请求头/响应头
  - 请求体内容
  - 触发来源元素信息
  - 查询参数和重定向链

### 搜索和筛选
- **搜索框**：输入关键词，按 URL、状态码、方法、页面标题、触发元素搜索
- **方法下拉**：按 HTTP 方法筛选
- **API/全部切换**：一键过滤静态资源（图片、CSS、JS、字体、媒体），仅显示 API 请求
- **域名展开/折叠**：按域名分组管理请求
- **域名筛选清空**：选择某个域名后点击「清空」，确认框可选择仅清空当前筛选域名；后台会按完整捕获列表删除该域名的请求
- **清空全部**：会同步清理后台请求列表、未完成请求缓存、触发链缓存和浏览器工具栏徽标，避免旧数据被延迟保存重新带回

### 导出请求

支持三种导出格式：

1. **Postman Collection**：导出为 `postman_collection.json`，可在 Postman 中直接导入
2. **HAR**：导出为标准 HTTP Archive 格式
3. **cURL**：从详情面板直接复制为 cURL 命令

导出范围：
- **导出全部**：点击工具栏的「导出」按钮，由后台按完整捕获列表导出；即使弹窗只展示最近一批请求，也不会漏掉后台已保存的请求
- **导出选中**：勾选请求后点击「导出选中」，仅导出当前勾选的请求
- **导出并清空**：点击带清空图标的导出按钮，后台完成全量导出后再清空捕获列表

### 代理重放配置

将捕获的请求转发到本地或其他服务器：

1. 点击「⚙」按钮展开代理配置栏
2. 填写：
   - **目标地址**：接收请求的服务器地址（如 `http://localhost:3000`）
   - **路径替换**（可选）：将原请求路径替换为新的路径
   - **自定义 Cookie**（可选）：为转发请求附加的 Cookie
3. 点击「保存」

在请求详情面板中点击「发送到本地」即可将请求转发到配置的目标地址。

### 操作/API 映射视图

操作/API 映射视图用于按业务操作反查接口，例如在「用户管理」页面下查看「查询」「编辑」「保存」分别触发了哪些请求：

1. 点击工具栏的 `⛓ 操作API` 按钮切换至映射视图
2. 第一层按页面/模块分组，如「用户管理」
3. 第二层按点击操作分组，如「查询」「编辑」「保存」
4. 展开操作后查看该操作关联的请求序列（按 `#1, #2, #3...` 编号排列）
5. 未匹配到点击来源的请求会进入「未关联请求」
6. 链的有效期控制：
   - **硬上限**：点击后最多保持 15 秒
   - **软上限**：相邻请求间隔不超过 3 秒（防止定时器轮询被归入）
   - **并发链**：最多 5 条链并存，超出时淘汰最旧链
   - **防抖**：100ms 内重复点击不会创建新链
7. 若静态资源过多，可点击「API/全部」切换到 API 视图，隐藏脚本、样式、图片、字体等资源请求

## 技术架构

### 数据流

```
Main World (页面)           Isolated World (content.js)    Service Worker (background.js)
     │                              │                              │
     │──fetch/XHR拦截──────────────►│                              │
     │──postMessage                 │──chrome.runtime.sendMessage──►│
     │  (captured request)          │   (CAPTURED_REQUEST)          │──匹配 webRequest 事件
     │                              │                              │──丰富请求信息
     │                              │                              │──存储到 capturedRequests
     │                              │                              │
     │                              │                              │──端口推送 ──► Popup
     │                              │                              │   (NEW_REQUEST)
```

### 核心组件

- **Main World Injection**（background.js + injected.js）：通过 `chrome.scripting.executeScript({ world: 'MAIN' })` 注入拦截代码，避免页面 CSP 拦截内联脚本；重写 `window.fetch` 和 `XMLHttpRequest.prototype` 以捕获请求
- **点击追踪**：捕获阶段监听 `click` 事件，遍历 DOM 树查找可交互元素，记录元素信息
- **页面上下文追踪**：监听 `pushState` / `replaceState` / `popstate` / `hashchange` 事件，实时更新页面 URL 和标题
- **调用链追踪**（content.js 注入代码）：使用 `__activeTraces` 数组支持最多 5 条并发调用链。每次点击创建新链，后续请求通过 `findMatchingTrace()` 匹配最近活跃链。双阈值控制（TTL 15s + GAP 3s）防止轮询请求错误归入。扁平顺序链（`#1, #2, #3...`）避免深度嵌套
- **Service Worker**：处理 `chrome.webRequest` 事件（onBeforeRequest、onBeforeSendHeaders、onHeadersReceived），合并主世界捕获的请求头和请求体信息
- **端口通信**：通过 `chrome.runtime.connect` 建立长连接，实时推送新请求到弹出面板
